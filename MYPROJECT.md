# Our project: normalization × depth in GNN+

## Summary

Base paper: Luo, Shi & Wu, *Can Classic GNNs Be Strong Baselines for
Graph-level Tasks? Simple Architectures Meet Excellence*, ICML 2025.
Upstream code: <https://github.com/LUOyk1999/GNNPlus> (cloned at commit
`0e02ad9`).

The paper's GNN+ recipe combines six ingredients, and reports that residual
connections let classic GNNs go as deep as 20 layers. But normalization is the
one ingredient that is **hard-coded** in the released code
(`self.batch_norm = True`), and only BatchNorm is ever tested. We turn it into
a configurable component and ask whether the depth claim depends on *which*
normalization is used.

## Hypothesis

1. Removing normalization (`none`) degrades performance — reproduces the
   published ablation.
2. BatchNorm is strong at shallow depth but weakens at 20 layers, because
   GraphGym batches ~32 small ZINC graphs, making per-batch statistics noisy.
3. Graph-aware alternatives (GraphNorm, PairNorm) are more stable at depth.

## Implementation

New file `GNNPlus/layer/norm.py` provides `build_norm(name, dim)`:

- `batch` — `nn.BatchNorm1d` (default, identical to upstream)
- `layer` — `nn.LayerNorm`
- `graph` — GraphNorm with learnable global/per-graph mean mixing [1]
- `pair` — PairNorm (no parameters) [2]
- `none` — identity control

All share `forward(x, batch)`, where `batch` is the PyG graph-index vector;
GraphNorm uses it, the others ignore it. The config key `cfg.gnn.norm` is
registered in `GNNPlus/config/custom_gnn_config.py` with default `'batch'`.
The four convolution layers read that key instead of hard-coding BatchNorm.
`MYPROJECT_CHANGES.diff` contains the exact tracked-file patch.

## Experiments

Dataset: ZINC subset (~12k molecular graphs, auto-downloaded by PyG).
Backbone: `custom_gnn` with `layer_type: gcne` (GCN+). Factors:
normalization ∈ {batch, layer, graph, pair, none} × depth ∈ {4, 8, 12, 20},
3 seeds per cell. Metric: test MAE (lower is better), mean ± std over seeds,
selected at the best validation epoch (GraphGym `argmin` on `mae`). Budget:
300 epochs per run (paper: 2000), with key cells re-run at 2000 epochs.

Commands:

```bash
python experiments/test_norm_smoke.py
python experiments/run_norm_study.py --repeat 3 --epochs 300
python experiments/aggregate_norm_study.py
```

Output: `results/norm_study_summary.csv` / `.md`.

## Integrity note

All tables in the submitted report are generated by
`aggregate_norm_study.py` from the `stats.json` files produced by
`main.py`; no numbers are hand-written. `docs/build_reports.py` reads
`results/norm_study_summary.csv`: when it exists, Table 3, Figure 1 and the
Section 4/6 conclusions are computed directly from it; when it is absent the
report marks the table explicitly as *pending* rather than inventing values.
GPU results should be copied back into `results/` — the aggregated CSV/MD are
committed so reviewers can check every reported number, while the per-run
`stats.json` files stay ignored by git. Report PDFs are written to the course
stage folders (or to a custom folder via `--out-dir` on Colab).
